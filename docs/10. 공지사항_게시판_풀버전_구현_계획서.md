# [공지사항 풀버전 (내용보기+페이징) 구현 계획서]

사용자님의 추가 요청에 따라, 단순 5개 링크 제공 위젯을 넘어 **'독립적인 공지사항 게시판(풀버전)'**으로 고도화하는 작업을 진행합니다.

## User Review Required

> [!IMPORTANT]
> **크롤링 소요 시간 안내**
> 기존에는 제목만 5개 가져와서 1초 만에 끝났지만, 모든 글의 '내용'까지 가져오려면 파이썬 로봇이 수십 개의 페이지를 일일이 들어가야 합니다. 데이터 수집에 약 10~30초 정도 소요될 수 있습니다. (물론 웹페이지 접속자에게는 지연이 없습니다. 백그라운드 로봇 작업입니다.)

## Open Questions

> [!NOTE]
> 1. **수집 범위**: 전체 공지사항을 전부 긁어오면 너무 오래 걸릴 수 있습니다. **최근 30~50개(약 3~5페이지 분량)** 정도만 긁어오는 것으로 제한을 둘까요?
> 2. **본문 이미지 처리**: 원본 공지사항에 첨부된 '이미지'나 '표' 데이터가 있을 경우, 이를 100% 똑같이 가져오려면 원본 서버 링크를 참조해야 합니다. 간혹 엑스박스가 뜰 수 있는데, 최대한 원본을 유지하는 방향으로 긁어올까요?

## Proposed Changes

### 1. 파이썬 스크롤러 로직 고도화 (`scripts/fetch_notices.py`)
- **[MODIFY]**: 단일 페이지 탐색에서 다중 페이지(Pagination) 탐색 로직으로 변경.
- 각 공지사항 상세 링크로 진입하여 본문 내용(`HTML`)을 추출.
- `title`, `date`, `content`(본문), `url` 형태의 심화된 JSON 구조로 저장.

### 2. 프론트엔드 UI: 본문 열기 (Accordion)
- **[MODIFY]**: `index.html` 내 공지사항 렌더링 로직 수정.
- 클릭 시 새 창으로 가지 않고, **해당 줄 아래로 본문 내용이 부드럽게 펼쳐지는 아코디언(Accordion) 방식** 도입.

### 3. 프론트엔드 UI: 페이징 (Pagination)
- **[MODIFY]**: 스크린샷으로 주신 것과 동일한 원형/오렌지색 하이라이트 형태의 페이징 버튼 네비게이션 하단 추가.
- 자바스크립트를 이용해 한 페이지당 10개씩 노출되도록 클라이언트 사이드 라우팅 적용.
