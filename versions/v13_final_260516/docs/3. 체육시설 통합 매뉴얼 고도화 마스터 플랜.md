# 🏗️ 체육시설 통합 매뉴얼 고도화 마스터 플랜

> [!IMPORTANT]
> **📌 작업 원칙 및 통합 요약 (필독)**
> 1. **파일 네이밍 규칙 100% 준수**: 앞으로 생성되는 모든 기획/계획 문서는 반드시 `docs/제목.md` 형태로 통일하여 관리합니다. (폴더 오작성 방지를 위해 파일명에 빗금 `/` 사용을 엄격히 금지합니다.)
> 2. **단일 마스터 플랜 통합**: 본 문서는 다음 3가지 핵심 과제를 하나로 합친 최종 마스터 플랜입니다.
>    - **파일/폴더 정리 (GitHub 마이그레이션)**: 레거시 구조 정리 및 정적 호스팅 파일 배치 최적화.
>    - **모바일 반응형 UI 이식**: 터치 친화적인 아코디언 오버레이 사이드바 및 모바일 1열 카드 정렬 적용.
>    - **SPA 유지 및 마크다운 전면 도입**: 화면 뼈대 변화(깜빡임) 없는 부드러운 매뉴얼 로딩 및 `.md` 포맷 기반의 유지보수 혁신.

본 계획서는 기존 GitLab 환경의 `manual-8` 프로젝트(v4 시스템)를 GitHub 정적 호스팅(Static Hosting) 환경으로 마이그레이션하면서, 최신 UI/UX(아코디언 사이드바, SPA 구조)를 적용하고 유지보수를 극대화하는 **통합 리팩토링 및 고도화 마스터 플랜**입니다.

---

## 1. 📂 아키텍처 및 디렉토리 리팩토링 (GitHub 마이그레이션)
불필요한 레거시 폴더(`public`, `backup` 등)를 정리하고 표준화된 구조로 재배치합니다.

*   `assets/`: 모든 정적 자원(CSS, JS, 이미지, 아이콘)을 한 곳으로 통합.
*   `docs/`: 프로젝트 관련 설명서, 마이그레이션 기획 문서 등 마크다운 기반의 기획/관리 전용 폴더.
*   `data/`: 기존 하드코딩된 데이터나 Markdown 매뉴얼 파일들이 위치할 저장소.
*   `pages/`: 대시보드가 아닌 별도의 전체 화면 HTML 페이지들 (개인정보처리방침, 이용약관 등 법적 고지 페이지 포함).
*   `versions/` 및 `_unclassified/`: 히스토리 파악을 위한 구버전 및 미분류 파일 격리 보관.

---

## 2. 📱 100% 모바일 완전 반응형 (Mobile-First UI)
모바일 환경에서 현장 직원들이 장갑을 끼거나 이동 중에도 불편함이 없도록 최적화합니다.

*   **터치 친화적 타겟**: 모바일에서 모든 메뉴와 버튼의 클릭 영역(최소 44x44px)을 확보하여 오터치 방지.
*   **오버레이 사이드바(Overlay Sidebar)**: 모바일에서는 사이드바가 기본적으로 숨겨져 있다가 햄버거 버튼 클릭 시 화면을 부드럽게 덮는 형태로 동작.
*   **카드 스태킹(Stacking)**: 메인 대시보드의 그리드는 모바일에서 세로 1열로 자동 정렬.
*   **Sticky 검색창 & 헤더**: 스크롤을 내려도 상단에 검색과 내비게이션 요소가 고정되어 즉각적인 조작 가능.

## 3. 🧩 단일 구조(SPA) 유지 및 마크다운(Markdown) 전면 도입

> **사용자 의견 반영**: "타고 들어갔는데 다른 구조면 혼동이 있을 것 같다"는 의견에 따라 내비게이션 위치를 고정하고, 문서 관리를 혁신적으로 개선합니다.

*   **단일 페이지 애플리케이션(SPA) 구조 유지**:
    *   헤더, 사이드바, 푸터는 **고정된 프레임(Shell)**으로 유지하여 시각적 안정감을 줍니다.
    *   사용자가 매뉴얼을 클릭하면 우측의 '대시보드 카드들'만 사라지고, 그 자리에 문서 내용이 부드럽게 삽입됩니다.
    *   **Context 유지**: 상단에 브레드크럼(예: `홈 > 매뉴얼 > 기술 매뉴얼`)과 `< 뒤로가기` 버튼을 배치하여 언제든 기존 화면으로 복귀 가능합니다.
*   **마크다운(Markdown) 기반 매뉴얼 관리**:
    *   HTML 태그 없이 텍스트만으로 쉽게 작성 및 수정 가능.
    *   **GitHub 최적화**: 깃허브 웹 화면에서 `.md` 파일을 열고 Edit(연필) 버튼으로 직접 내용을 수정하면 즉시 배포됨. (사실상 깃허브가 관리자 페이지 역할 수행)
    *   `marked.js`를 통해 마크다운을 HTML로 파싱하고, `DOMPurify`로 XSS 보안 검증 후 화면에 렌더링.
*   **하이브리드 문서 검색 전략 (투트랙 방식 도입)**:
    *   **문제 극복**: 정적 자바스크립트는 대용량 PDF 내부 텍스트를 직접 스캔할 수 없는 한계가 존재.
    *   **해결 (메타데이터 태깅)**: 검색용 JSON 데이터에 PDF 문서의 핵심 목차 및 키워드(예: "심폐소생술", "소화기", "대피로")를 숨겨진 메타데이터(Metadata)로 사전 입력.
    *   **UX 흐름**: 메인 검색창에서 키워드 검색 시 해당 문서를 정확히 찾아주고, 상세 단어 위치는 브라우저 내장 PDF 뷰어의 `Ctrl+F` 기능을 활용하도록 안내.

## 4. 🛠️ 단계별 구현 계획 (Implementation Steps)

### 📌 [선제 조건] 시큐어 코딩 마스터 지침 준수
모든 코딩 및 개발 작업은 **`docs/SOS 프로젝트 시큐어 코딩 마스터 지침.md`** 에 명시된 4대 원칙(보안, 개인정보 보호 마스킹, 웹 접근성, 호환성)을 100% 필수 선제 조건으로 하여 진행됩니다.

### Phase 1: 기반 구조 마이그레이션 및 뼈대 구축
*   GitHub 호스팅을 위한 불필요 폴더 제거 및 `assets/`, `docs/`, `data/` 구조로 파일 전면 재배치.
*   v4 메인 시스템(`index.html`)에 Tailwind 레이아웃과 커스텀 사이드바 CSS 병합.
*   아코디언 사이드바 및 오버레이(모바일 반응형) 로직 이식.

### Phase 2: 아이콘 전면 교체 및 UI 최적화
*   기존 `Lucide` 아이콘 전체를 `Phosphor` 아이콘으로 일괄 교체 (시설별 맞춤 아이콘 적용).
*   다크모드 기능 및 모바일 반응형 최적화(햄버거 토글 등) 적용.

### Phase 3: SPA 라우팅 및 마크다운(Markdown) 시스템 구현
*   기존 `index_content_v2.js`의 외부 로딩 로직을 개선하여 Markdown(.md) 파일을 파싱하도록 변경 (`marked.js` 연동).
*   DOMPurify를 추가하여 렌더링 보안 강화.
*   브레드크럼 및 뒤로가기 내비게이션 구현.

### Phase 4: 컴플라이언스 및 최신 보안 지침 적용
*   **「국가 사이버보안 기본지침」(2026.5.1 개정) 완벽 준수 전략**:
    1.  **N2SF(국가 망 보안체계) 등급 분류**: 본 매뉴얼 시스템은 GitHub 정적 호스팅을 사용하므로, 취급 데이터를 **'공개(O, Open)'** 또는 **'민감(S, Sensitive)'** 등급으로 명확히 분류하여 보안 정책 적용.
    2.  **MFA(다중인증) 의무화 적용**: GitHub를 통해 매뉴얼을 수정하는 모든 시스템 관리자(사이버보안 담당자) 계정에 **2FA(2단계 인증) 설정을 필수 가이드라인으로 강제화**.
    3.  **용어 정비**: 기존 '정보보안'이라는 명칭을 개정안에 맞게 **'사이버보안'**으로 문서 내 일괄 변경.
    4.  **플러그인 없는(Plugin-free) 보안**: ActiveX 등 설치형 보안 프로그램 없이 웹 표준 자체 보안(`DOMPurify` 기반 XSS 방어)만으로 시스템 보호.
*   개인정보 처리방침, 이용약관 등 푸터 링크 연동.
*   GitHub 웹 환경에서 손쉽게 마크다운 매뉴얼을 추가하고 수정하는 **관리자 가이드라인(README.md)** 작성 (MFA 설정 안내 포함).
